## 3. QA 수정 로그

### 3-1. 추천 route 정리
#### 문제
- 추천 로직이 혼합되어 기준이 불명확

#### 조치
- `recommendations/route.ts` 기준으로 정리
- `user_type`, 스크랩 메타, reranking 반영

#### 결과
- 추천 안정성 개선
- 프로필/스크랩 기반 추천 구조 정리됨

---

### 3-2. 챗봇 프로필 인식 실패
#### 문제
- 프로필 있음에도 다시 입력 요구

#### 원인
- `user_info` 매핑 오류
- route 쪽 프로필 조회 실패 시 fallback으로 빠지는 구조

#### 조치
- route + page 프로필 전달 구조 보강
- 현재 페이지의 `savedFilter/current profile`도 fallback으로 전달

#### 결과
- 프로필 기반 추천 정상 동작

---

### 3-3. 질문-프로필 충돌 처리
#### 문제
- 충돌 시 바로 검색 진행

#### 조치
- 질문 vs 프로필 비교 후 confirm 질문 반환

#### 결과
- 충돌 시 확인 질문 정상 출력

---

### 3-4. 승인 응답 처리
#### 문제
- `"응"`, `"그래줘"`뿐 아니라 `"웅"` 같은 짧은 승인 응답 처리 불안정
- 일부 케이스에서 승인 후 다시 조건 입력 fallback으로 빠짐

#### 조치
- 긍정 응답 패턴 추가
- `pending/active override` 분리
- confirm 승인 시 `pendingOverride.query`를 재실행하도록 정리
- confirm 승인 시 `history/recent_results` contamination 제거
- confirm 승인 요청은 `general/refinement/fallback` 분기보다 우선 처리되도록 수정

#### 결과
- 아래 응답은 승인으로 정상 처리됨
  - `응`
  - `웅`
  - `응 그래줘`
  - `그래`
  - `좋아 진행해줘`

---

### 3-5. 거절 응답 처리
#### 문제
- confirm 질문 뒤 `"아니"`, `"취소"` 같은 거절 응답에 대한 처리 부재

#### 조치
- negative 응답 시:
  - `pendingOverride` 즉시 초기화
  - `active override`는 변경하지 않음
  - 검색 실행 없이 안내문만 반환하도록 정리

#### 안내 문구
> 알겠습니다. 기존 프로필 기준으로 다시 찾아드릴까요,  
> 아니면 원하시는 조건을 다시 말씀해주실까요?

#### 결과
- `"아니"`, `"취소"` 등 거절 응답 처리 정상 동작

---

### 3-6. history 오염 문제
#### 문제
- 다른 채팅방 맥락 섞임
- confirm 승인 시에도 기존 history가 함께 전달되어 분기 오염 가능성 존재

#### 조치
- active chat 기준으로 history 제한
- confirm 승인 시에는 `history=[]`, `recent_results=[]`로 전달하여 contamination 제거
- 다른 채팅방 history는 계속 사용 금지

#### 결과
- 채팅방 독립성 확보
- confirm 승인 이후 fallback/general로 꼬이던 문제 완화

---

### 3-7. 후속질문 refinement
#### 문제
- `"그중"`, `"마감 임박"` 처리 실패

#### 원인
- 직전 결과 메타데이터 미전달
- refinement intent 인식 부족

#### 조치
- `recent_results` 전달
- refinement 키워드 인식 추가
- confirm 승인 시에는 contamination 제거만 적용하고, 일반 후속질문에서는 refinement 흐름 유지

#### 결과
- `"그중 마감 임박만 보여줘"` 기본 동작 확인
- 다만 refinement가 항상 “직전 결과 집합만” 사용하는지는 추가 확인 필요

---

### 3-8. 프로필 참조 표현 처리
#### 문제
- `"내 저장 정보"` 이해 못함

#### 조치
- 프로필 참조 키워드 추가
  - `내 저장 정보`
  - `내 프로필`
  - `내 조건`
  - `내 조건에 맞는 공고`

#### 결과
- 자연어 표현 대응 개선

---

### 3-9. fallback 혼합 버그
#### 문제
- `"추천했어요" + "못찾았어요"` 동시에 출력

#### 원인
- `policies` 비어있는데 prefix가 붙는 구조
- 프로필 기반 질문이 그대로 약한 semantic query로 들어가는 문제

#### 조치
- 결과 있을 때만 prefix 출력
- 검색 완화 로직 추가
- 메타데이터 fallback 후보 구성

#### 결과
- fallback 혼합 버그 완화
- 프로필 기반 추천 안정성 향상

## 8. override 승인 처리 구조 (중요 수정 사항)

### 문제 배경
- override(조건 변경) 확인 질문 이후  
  `"응"`, `"웅"`, `"그래줘"` 등의 승인 응답이 들어왔을 때  
  일관되게 검색이 실행되지 않는 문제 발생

- 일부 케이스에서는:
  - 승인 이후에도 다시 조건 입력 요청
  - fallback으로 흐름이 끊김
  - 승인 응답이 일반 대화처럼 처리됨

---

### 원인 정리

1. 승인 응답을 자연어로만 해석하려고 했던 구조
2. `pending override → active override` 전환 이후 실제 재실행 흐름이 불안정
3. 승인 이후 `history/recent_results`가 함께 전달되어 contamination 발생
4. 서버에서 confirm 승인 요청이 다른 intent 분기(`general/refinement/fallback`)보다 먼저 처리되지 않음

---

### 핵심 개념

override 승인은 "자연어 이해 문제"가 아니라  
"상태 전환(state transition)" 문제로 정의함

즉,

- LLM → 의미 해석
- 코드 → 상태 결정 (확정 / 분기 / 실행)

으로 역할 분리 필요

---

### 수정 방향

#### 1. deterministic rule 도입 (의도적 설계)

다음 응답은 승인으로 처리:

- 응
- 웅
- 네
- 그래
- 그래줘
- 응 그래줘
- 그렇게 해줘
- 좋아 진행해줘

※ 이 부분은 하드코딩이 아니라 UX 안정성을 위한 상태 제어 로직

---

#### 2. 상태 흐름 명확화

```text
confirm 질문 발생
→ pending override 저장
→ 사용자 승인 (affirmative)
→ pendingOverride.query 재실행
→ active override 유지
→ confirm 승인 시 history/recent contamination 제거
→ 결과 반환
